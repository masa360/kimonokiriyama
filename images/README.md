# 画像フォルダ

プラン選択の「こんな写真が撮れます」ボタンで出す写真を置く。

## ファイル名（この名前で置くこと）

コード側がこの名前を直接見ている。名前が違うと表示されない。

| ファイル名 | プラン | 状態 |
| :-- | :-- | :-- |
| `honkaku.jpg` | 和装本格着付け（49,500円） | 掲載中 |
| `taiken.jpg` | 和装体験（22,000円） | **仮。差し替え予定** |

> ⚠️ `taiken.jpg` は衣装のみ（人が着ていない）の写真。
> 本格着付けは着た姿なので、**安い方だけ実物が見えない**状態になっている。
> 「服の上から羽織った状態の全身」が届いたら、同じ名前で上書きすること。

**各プラン1枚だけ**。

## 打掛ギャラリー

サービス説明の下に出る「お衣装（打掛）を見る」ボタンで開く。

| ファイル名 |
| :-- |
| `kimono-1.jpg` 〜 `kimono-5.jpg` |

**5枚揃っていなくてよい。** 実在する分だけを自動で拾う。
欠番があっても詰めて表示する（例：1・3・5 だけでも動く）。
1枚も無ければボタンごと出ない。

> ⚠️ **衣装の「指定」はしない。**
> システムは在庫を知らないため、同じ日に2組が同じ衣装を選べてしまう。
> ここは雰囲気を見せるだけで、選ぶのは当日その場。
> 画面には「当日お選びいただけます・写真は一例です」と出る。

> 写真が無いプランは、ボタンごと表示されない。
> 押しても何も出ないボタンは、お客様には不具合に見えるため。
> つまり `taiken.jpg` を置いた瞬間に、体験側のボタンが現れる。

## 写真の条件

| 項目 | 目安 |
| :-- | :-- |
| 形式 | JPG |
| 幅 | **1200px 程度**。これより大きいと読み込みが遅い |
| 容量 | **300KB以下**。スマホで見る前提 |
| 向き | 縦でも横でもよい（画面に合わせて収まる） |

> リポジトリに画像を入れると、GitHub Pages がそのまま配信する。
> 重い画像を置くと、その分ページの表示が遅くなる。

## 体験プランの写真で気をつけたいこと

差額は27,500円ある。**その差が写真で分かること**が大事。

| プラン | 見せたい状態 |
| :-- | :-- |
| 和装体験 | **服の上から羽織った状態**。ヘアセットなしと分かるもの |
| 和装本格着付け | しっかり着た全身。ヘアセットあり |

⚠️ 体験プランの写真が本格着付けに見えてしまうと、
当日「話が違う」になる。**ヘアセットの有無が見分けられる**ものを選ぶこと。

⚠️ 人物が写る写真は、**掲載の許可を得てから**置くこと。

## 大きい画像が届いたとき

スマホで見る前提なので、**300KBを超えたら縮める**。
重いと、見る前に離脱される。

```python
from PIL import Image
im = Image.open("元の画像.jpg")
r = min(1200 / im.width, 1200 / im.height, 1.0)   # 長辺1200pxに収める
im.resize((round(im.width * r), round(im.height * r)), Image.LANCZOS)   .save("taiken.jpg", "JPEG", quality=85, optimize=True, progressive=True)
```

実績：2448×2581px / 1,636KB → 1138×1200px / 287KB（表示サイズでは劣化が分からない）
